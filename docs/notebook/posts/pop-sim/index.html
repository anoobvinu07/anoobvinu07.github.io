Simulating Populations: Allele and Genotype Frequencies

hpc
r
bioinformatics

sample(), replicate(), and combining populations with rbind()
Author

Anoob Prakash

Published

September 16, 2026

Goal

Simulate two populations at a single biallelic gene using sample() and replicate(), calculate genotype and allele frequencies for each, then combine them into one table to explore how those frequencies shift with population size and starting allele frequency.

Prerequisites

  • Completed Modules 1–2 (functions, if/else, for loops, table(), grouped summaries)
  • No external dataset needed — this module is entirely simulation-based

Learning objectives

By the end of this module you should be able to:

  • Use sample() to draw alleles for an individual under a given allele frequency
  • Use replicate() to generate genotypes for many individuals, and for many simulated populations
  • Calculate genotype frequencies (AA, Aa, aa) and allele frequencies (A, a) from simulated data
  • Explain the difference between rbind()/bind_rows() (stacking rows) and merge()/*_join() (matching rows by a shared key), and pick the right one for combining populations
  • Combine two or more simulated populations into a single data frame and compute frequencies per population
  • Observe how sampling variance in allele frequency depends on population size — a first hands-on look at genetic drift

Section 1: One individual, one gene

A diploid individual carries two copies of a gene. If the population-wide frequency of allele A is p, you can simulate one individual’s two allele copies as two independent draws from sample():

p <- 0.6
sample(c("A", "a"), size = 2, replace = TRUE, prob = c(p, 1 - p))

replace = TRUE matters here: you’re drawing each allele copy independently from the population’s gene pool, not drawing two different alleles without putting the first one back.

A tempting but fragile shortcut is to paste the two draws together directly:

paste(sample(c("A", "a"), size = 2, replace = TRUE, prob = c(p, 1 - p)), collapse = "")

Run this several times and you’ll see "AA", "Aa", "aA", and "aa" — but "Aa" and "aA" are the same genotype, and table() would count them as two different categories. The fix is to count copies of the reference allele instead of concatenating the raw draw order:

simulate_genotype <- function(p) {
  
  # simulate with sample function
  alleles <- sample(c("A", "a"), 
              size = 2, 
              replace = TRUE, 
              prob = c(p, 1 - p))

  n_A <- sum(alleles == "A")
  
  # if else statement
  if (n_A == 2) {
    "AA"
  } else if (n_A == 1) {
    "Aa"
  } else {
    "aa"
  }
}

simulate_genotype(0.6)

Section 2: One population, many individuals — replicate()

replicate() repeats an expression a fixed number of times and collects the results — exactly what you need to generate genotypes for many individuals:

simulate_population <- function(n, p) {
  genotypes <- replicate(n, simulate_genotype(p))
  data.frame(individual = seq_len(n), genotype = genotypes, stringsAsFactors = FALSE)
}

pop_demo <- simulate_population(n = 20, p = 0.5)
head(pop_demo)

Section 3: Genotype frequencies

geno_counts <- table(factor(pop_demo$genotype, levels = c("AA", "Aa", "aa")))
geno_freq   <- prop.table(geno_counts)
geno_freq

Wrapping the genotype column in factor(..., levels = c("AA","Aa","aa")) guarantees all three categories show up — including with a count of zero — instead of silently dropping a genotype that happened not to appear.

Compare this to the Hardy-Weinberg expectation for allele frequency p:

hwe_expected <- function(p) {
  q <- 1 - p
  c(AA = p^2, Aa = 2 * p * q, aa = q^2)
}
hwe_expected(0.5)

Section 4: Allele frequencies from genotypes

Break each genotype string back into its two alleles and tally them:

allele_freq <- function(genotype_vec) {
  alleles <- unlist(strsplit(genotype_vec, ""))
  prop.table(table(alleles))
}

allele_freq(pop_demo$genotype)

The two allele frequencies should sum to 1 — a quick sanity check worth building into any script.

Section 5: Two populations, and combining them with rbind()

pop1 <- simulate_population(n = 40, p = 0.7)
pop1$population <- "Pop1"

pop2 <- simulate_population(n = 15, p = 0.3)
pop2$population <- "Pop2"

combined <- rbind(pop1, pop2)
combined <- combined[, c("population", "individual", "genotype")]

table(combined$population)   # should read Pop1 = 40, Pop2 = 15

rbind() vs. join(): which one do you need?

  • rbind() (base R) or dplyr::bind_rows() — stack rows from two objects that already share the same columns. This is how you combine two independently simulated populations into one long table, which is exactly what “adding populations together” means here.
  • merge() (base R) or dplyr::*_join() (left_join(), inner_join(), etc.) — match rows across two tables by a shared key column (e.g., attaching environmental data to individuals by an ID). This solves a different problem and is not what you want for stacking two simulated populations.

For this exercise, rbind() is the right tool.

genotype_freq_by_pop <- tapply(

Section 7: Exploring the effect of population size (genetic drift)

Simulate populations of different sizes at the same true allele frequency, many times over, and look at how much the simulated allele frequency bounces around:

sizes  <- c(5, 20, 50, 200)
p_true <- 0.5
n_reps <- 100

drift_list <- lapply(sizes, function(n) {
  freqs <- replicate(n_reps, {
    pop <- simulate_population(n, p_true)
    af  <- allele_freq(pop$genotype)
    unname(af["A"])
  })
  data.frame(size = n, replicate = seq_len(n_reps), freq_A = freqs)
})

drift_df <- do.call(rbind, drift_list)

aggregate(freq_A ~ size, data = drift_df, FUN = sd)

boxplot(freq_A ~ size, data = drift_df,
        xlab = "Population size", ylab = "Simulated allele frequency (A)",
        main = "Sampling variance shrinks as population size grows")
abline(h = p_true, col = "red", lty = 2)

Smaller populations show a much wider spread of simulated allele frequencies around the true value (the red dashed line) than larger ones — this is genetic drift in its simplest form: random sampling of gametes causes allele frequencies to bounce around more when fewer individuals are sampled each generation.

Section 8: Exploring the effect of starting allele frequency

Hold population size fixed and vary p instead, comparing observed genotype frequencies to the Hardy-Weinberg expectation:

p_values <- c(0.1, 0.3, 0.5, 0.7, 0.9)
n_fixed  <- 50

geno_freq_list <- lapply(p_values, function(p) {
  pop <- simulate_population(n_fixed, p)
  observed <- prop.table(table(factor(pop$genotype, levels = c("AA", "Aa", "aa"))))
  expected <- hwe_expected(p)
  data.frame(p = p, genotype = names(observed),
             observed = as.numeric(observed),
             expected = as.numeric(expected[names(observed)]))
})

geno_freq_df <- do.call(rbind, geno_freq_list)
geno_freq_df

Notice that Aa (heterozygote) frequency peaks at intermediate p, exactly as 2pq predicts.

Idea check

Work through these before the exercises.

  1. Why does simulate_genotype() draw with replace = TRUE instead of replace = FALSE?
  2. What goes wrong if you tally genotypes by pasting the two sampled alleles directly (paste(alleles, collapse = "")) instead of counting copies of A? How does simulate_genotype() avoid that problem?
  3. What is the practical difference between rbind() and a join() such as merge() or dplyr::left_join()? Why is rbind() the correct choice for combining two independently simulated populations?
  4. Under Hardy-Weinberg equilibrium with allele frequency p, what are the expected genotype frequencies for AA, Aa, and aa? At what value of p is the heterozygote frequency (Aa) maximized?
  5. If you simulate a population of size 10 versus size 500 at the same true p, what do you expect to happen to the spread of the resulting allele-frequency estimates across many replicate simulations — and why?
  6. Why is factor(genotype, levels = c("AA","Aa","aa")) used before calling table(), rather than just calling table(genotype) directly?
  7. Why might a small, isolated real forest population show allele frequencies that drift further from an “expected” value than a large, well-connected population?

Practical exercises

  1. Write simulate_genotype(p) and generate a genotype for one individual at p = 0.5 ten separate times. Confirm you see a mix of AA, Aa, and aa.
  2. Write simulate_population(n, p) using replicate() and generate a population of n = 50 individuals at p = 0.5.
  3. Calculate genotype frequencies for this population with table()/prop.table(), and compare them to hwe_expected(0.5).
  4. Write allele_freq() and calculate allele frequencies for the same population. Confirm the two frequencies sum to 1.
  5. Simulate a second population with a size and allele frequency of your choosing (different from step 2), and calculate its genotype and allele frequencies.
  6. Combine both populations into a single data frame using rbind(). Confirm the combined data frame has the expected total number of rows and a population column identifying each row’s origin.
  7. Use tapply() (or by()) on the combined data frame to calculate genotype and allele frequencies separately per population, and confirm the results match what you got individually in steps 3–5.
  8. Run the population-size drift experiment from Section 7 using sizes c(5, 20, 50, 200), p_true = 0.5, and n_reps = 100. Produce the boxplot and describe the pattern in one sentence.
  9. Run the allele-frequency experiment from Section 8 using p_values <- c(0.1, 0.3, 0.5, 0.7, 0.9) at n = 50. Confirm your observed Aa frequencies roughly track 2pq across the range of p.
  10. Save every table you produced (genotype frequencies, allele frequencies, the drift summary, the observed-vs-expected table) to results/, and the boxplot as a PNG.

Homework (weeks 1–2)

Build a self-contained src/03_simulate_populations.R that:

  • Defines reusable simulate_genotype(), simulate_population(), allele_freq(), and hwe_expected() functions.
  • Simulates at least 3 populations with different combinations of size and starting allele frequency, and combines them with rbind() into one data frame.
  • Computes and saves a clean per-population summary table of genotype and allele frequencies to results/.
  • Runs a drift experiment (as in Section 7) with at least 4 population sizes and at least 50 replicates each at a fixed p, and saves the boxplot of allele-frequency spread by size to results/.
  • Includes a written interpretation (half a page, as script comments or results/README.md) answering:
    • How does population size affect how far a single simulated population’s allele frequency can drift from the true p?
    • Connect this pattern to a real scenario in forest genetics — for example, small, fragmented, or edge-of-range tree populations versus large, continuous ones.

Bonus (optional): extend the simulation across non-overlapping generations — each generation, resample the next generation’s alleles from the previous generation’s genotype pool instead of from a fixed p. This is a minimal Wright-Fisher drift simulation and is a natural bridge toward the coalescent- and drift-aware methods used in genomic-offset validation work.

Submission format: src/03_simulate_populations.R, everything it generates in results/, and the written interpretation.

Suggested pace: 2–3 hours per week over 1–2 weeks.
