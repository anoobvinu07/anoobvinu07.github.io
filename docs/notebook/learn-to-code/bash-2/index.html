bash: Advanced commands to work with Linux systems

Navigation, head/wc/cat, redirection, quoting, and the errors every beginner hits.

Every example below has a copy button (top-right of the block). Lines starting with # are comments. Grey-green blocks show what the terminal prints back.

Assumes bash with GNU coreutils, as on most Linux clusters. Slurm is used for scheduler examples. Prefer an app-style view? Open the interactive version.

Getting oriented

Where you are, what the prompt is telling you, and how to get help without leaving the terminal.

prompt — Read the prompt

The prompt tells you who you are, which machine you are on, and your current directory. On a cluster, the hostname matters: login nodes are shared and are not for heavy computation.

syntax
[user@host directory]$
hostname
login01.cluster.edu

Which node am I on? login01 = shared login node; c0423 = compute node.

whoami
ada

Your username, which is also the owner of your $HOME.

echo $HOME $SCRATCH
/home/ada /scratch/ada

Your home and scratch locations. $SCRATCH is site-specific; check your cluster docs.

Tip

~ at the end of the prompt means you are in your home directory.

Tip

A > prompt instead of $ means the shell is waiting for you to finish something, usually an unclosed quote. Press Ctrl-C to bail out.

Warning

Do not run long or memory-heavy jobs on a login node. Request a compute node with srun --pty bash or submit with sbatch (Slurm).

man / --help — Get help

Every standard command documents itself. --help gives a quick summary; man gives the full manual page.

syntax
man COMMAND   |   COMMAND --help   |   type COMMAND
head --help

Short usage summary for GNU tools.

man wc

Full manual. Space = next page, b = back, /word = search, q = quit.

type cd ls
cd is a shell builtin
ls is aliased to `ls --color=auto'

Is it a builtin, an alias, or a program on disk?

module avail samtools

On HPC, software is often hidden behind environment modules.

Tip

help cd works for shell builtins that have no man page.

shortcuts — Keyboard shortcuts

These save more time than any alias. Tab completion also prevents typos in long filenames.

syntax
Tab · Ctrl-C · Ctrl-D · Ctrl-R · Ctrl-A / Ctrl-E · ↑ ↓
# Tab        complete a file or command name (press twice to list options)
# Ctrl-C     cancel the running command / abandon the current line
# Ctrl-D     end of input; on an empty prompt it logs you out
# Ctrl-R     search backwards through history
# Ctrl-A / E jump to start / end of line
# Ctrl-L     clear the screen
# Up / Down  previous / next command

Reference, not something to run.

history | tail -n 20

Your last 20 commands.

!!

Re-run the previous command. sudo !! is the classic, but you rarely have sudo on a cluster.

Warning

Ctrl-S freezes terminal output in many terminals. If your screen stops responding, press Ctrl-Q.

File navigation

Moving around the filesystem, making and removing things, and finding files on a shared cluster.

pwd — Print working directory

Shows the absolute path of the directory you are in. Run it whenever you are unsure where a relative path will point.

syntax
pwd
pwd
/scratch/ada/project/fastq

ls — List directory contents

Lists files. Flags combine: -lh is the same as -l -h.

syntax
ls [-l] [-a] [-h] [-t] [-r] [PATH...]
ls -lh
-rw-r--r-- 1 ada lab 1.2G Oct  2 09:14 S01_R1.fastq.gz

Long listing with human-readable sizes (K, M, G).

ls -la

Include hidden dotfiles such as .bashrc.

ls -ltr

Sort by time, oldest first, so the newest file ends up next to your prompt.

ls *.vcf.gz

Glob: the shell expands the pattern before ls ever runs.

ls -d */

Directories only.

Tip

Read permissions as owner / group / others: rw-r--r-- means you can write, everyone else can only read.

Warning

ls on a directory with millions of files can hang the shared filesystem. Use ls -f | head or find . -maxdepth 1 | head.

cd — Change directory

Moves you to another directory. With no argument, it takes you home.

syntax
cd [PATH]
cd /scratch/$USER/project

Absolute path: starts with /, works from anywhere.

cd data/raw

Relative path: resolved from where you are now.

cd ..

Up one level. cd ../.. goes up two.

cd ~

Home. Plain cd does the same.

cd -

Back to the previous directory, like a TV remote’s ‘last channel’.

cd "My Data"

Quote names that contain spaces.

Tip

. is the current directory, .. is the parent, ~ is your home, / is the filesystem root.

paths — Absolute vs relative paths

An absolute path starts at / and means the same thing everywhere. A relative path depends on your current directory, which is why scripts that work interactively can fail inside a batch job.

syntax
/abs/path   rel/path   ./file   ../sibling   ~/file
realpath reads.fq
/scratch/ada/project/reads.fq

Turn a relative path into an absolute one.

cd "$SLURM_SUBMIT_DIR"

Inside a Slurm job script: start where you ran sbatch, so relative paths behave.

./run_qc.sh

Run a script in the current directory. The ./ is required because . is not on $PATH.

Warning

~ is not expanded inside quotes: "~/data" is a literal tilde. Use "$HOME/data".

mkdir — Make directories

Creates directories. -p creates parent directories as needed and does not complain if the directory already exists.

syntax
mkdir [-p] DIR...
mkdir results
mkdir -p results/qc/fastqc logs

Nested path plus a second directory in one call.

mkdir -p analysis/{raw,trimmed,aligned}

Brace expansion creates three sibling directories.

cp — Copy files

Copies files. Directories need -r. With several sources, the last argument must be a directory.

syntax
cp [-r] [-i] [-v] SOURCE... DEST
cp config.yaml config.yaml.bak

Quick backup before editing.

cp -r ref/ /scratch/$USER/ref/

Copy a directory tree.

cp -i *.vcf archive/

-i asks before overwriting anything.

rsync -avh --progress data/ /scratch/$USER/data/

For large transfers, rsync resumes and shows progress.

Warning

cp overwrites the destination silently unless you use -i or -n.

mv — Move or rename

Renaming and moving are the same operation. Moving within one filesystem is instant regardless of size.

syntax
mv [-i] [-n] SOURCE... DEST
mv sample1.fq S01_R1.fq

Rename.

mv *.log logs/

Move many files into a directory.

mv -n new.txt old.txt

-n never overwrites an existing file.

Warning

mv a.txt b.txt replaces b.txt without asking if it exists.

rm — Remove files

Deletes files permanently. There is no recycle bin on a cluster, and scratch is usually not backed up.

syntax
rm [-i] [-r] [-f] PATH...
rm tmp.txt
rm -i *.bam

Confirm each deletion.

rm -r old_run/

Remove a directory and everything in it.

ls *.tmp && rm *.tmp

Preview what a glob matches before deleting it.

rmdir empty_dir

Removes only empty directories: a safe default.

Warning

rm -rf $DIR/ with an empty $DIR becomes rm -rf /. Quote and guard: rm -rf "${DIR:?not set}"/.

Warning

A stray space is fatal: rm -rf ./ data deletes the current directory, not ./data.

find — Find files

Recursively searches a directory tree by name, type, size, or age. Quote the pattern so find, not the shell, does the matching.

syntax
find PATH [-name 'PATTERN'] [-type f|d] [-size +N] [-mtime -N]
find . -name '*.fastq.gz'

Every gzipped FASTQ below here.

find /scratch/$USER -type f -size +10G

Large files that are eating your quota.

find . -name '*.log' -mtime -1

Logs modified in the last 24 hours.

find . -maxdepth 1 -type d

Immediate subdirectories only.

find . -name '*.tmp' -print

Always run with -print first; only then swap it for -delete.

Warning

Unquoted find . -name *.txt breaks when the current directory already contains a .txt file, because the shell expands it first.

du / df / quota — Disk usage

Clusters enforce quotas. When writes start failing, these show where your space went.

syntax
du -sh PATH   |   df -h PATH   |   quota -s
du -sh *

Size of each item in the current directory.

du -sh * | sort -h

Same, sorted smallest to largest.

df -h $HOME

Free space on the filesystem holding your home.

quota -s

Your quota on many systems. Some sites use myquota, lfs quota, or a custom command.

ln -s — Symbolic links

A shortcut that points at another path. Useful for linking shared reference genomes into your project without copying them.

syntax
ln -s TARGET LINK_NAME
ln -s /shared/refs/Pinus_taeda_v2.fa ref.fa

ref.fa now points to the shared genome.

ls -l ref.fa
ref.fa -> /shared/refs/Pinus_taeda_v2.fa
Tip

The argument order matches cp: what exists first, then the new name.

Core utilities

Look inside files without opening an editor: cat, head, tail, wc, and the small tools you chain them with.

cat — Concatenate & print

Prints whole files to the screen, or joins several files into one stream. Best for small files.

syntax
cat [-n] [-A] FILE...
cat samples.txt

Print a short file.

cat -n samples.txt

Number every line.

cat part1.fq part2.fq > combined.fq

Join files. Order is preserved.

cat -A sheet.csv | head

Show hidden characters: ^M$ at line ends means Windows line endings.

Tip

Gzipped FASTQ files can be concatenated directly: cat a.fq.gz b.fq.gz > ab.fq.gz produces a valid gzip file.

Warning

Running cat on a 50 GB file floods your terminal. Use head or less instead.

Warning

cat with no filename waits for keyboard input. Press Ctrl-D (end) or Ctrl-C (cancel).

head — First lines

Shows the start of a file, 10 lines by default. Ideal for peeking at headers and file formats.

syntax
head [-n N] [-c BYTES] FILE...
head data.csv

First 10 lines.

head -n 4 reads.fastq

One FASTQ record is exactly 4 lines.

head -n -1 data.csv

GNU only: everything except the last line.

zcat reads.fastq.gz | head -n 8

Peek inside a gzipped file without decompressing it to disk.

head -n 1 *.csv

Several files: head prints a ==> name <== banner for each.

Warning

gzip: stdout: Broken pipe after zcat | head is harmless: head simply stopped reading early.

tail — Last lines

Shows the end of a file. -f keeps following it as it grows, which is how you watch a running job’s log.

syntax
tail [-n N] [-n +K] [-f] FILE
tail -n 20 slurm-123456.out

Last 20 lines of a job log.

tail -f slurm-123456.out

Live view. Ctrl-C stops watching; it does not stop the job.

tail -n +2 data.csv

Start at line 2, i.e. drop the header.

head -n 200 data.csv | tail -n 1

Print exactly line 200.

less — Page through a file

Opens a file one screen at a time without loading it all into memory. Safe on huge files.

syntax
less [-S] [-N] FILE
less -S variants.vcf

-S turns off line wrapping; use ← → to scroll wide VCF rows.

zless reads.fastq.gz

Page through a gzipped file.

# inside less:
#   Space / b   page down / up
#   g / G       start / end
#   /pattern    search forward, n = next match
#   q           quit

Keys to remember.

wc — Count lines, words, bytes

Counts lines (-l), words (-w), and bytes (-c). Strictly, -l counts newline characters.

syntax
wc [-l] [-w] [-c] FILE...
wc -l samples.txt
96 samples.txt

Filename is printed after the count.

wc -l < samples.txt
96

Read from stdin instead: you get just the number, handy in scripts.

echo $(( $(zcat reads.fq.gz | wc -l) / 4 ))

Number of reads in a FASTQ: lines divided by 4.

grep -vc '^#' variants.vcf

Count variant rows, skipping header lines (grep -c counts matches).

wc -l *.txt

Several files get a ‘total’ line at the end.

Warning

If the last line has no trailing newline, wc -l reports one fewer line than you expect.

sort / uniq — Sort and deduplicate

sort orders lines; uniq collapses adjacent duplicates. Because uniq only looks at neighbors, you almost always sort first.

syntax
sort [-n] [-h] [-r] [-k N] [-t SEP] [-u] FILE   |   uniq [-c] [-d]
sort -k2,2n coords.tsv

Sort numerically on column 2 only.

sort -t, -k3,3 data.csv

Comma-separated: sort on the third field.

cut -f1 calls.tsv | sort | uniq -c | sort -rn

Frequency table of column 1, most common first.

sort -u ids.txt

Sort and drop duplicates in one step.

Warning

Without -n, sort is alphabetical: 10 comes before 9.

cut — Extract columns

Pulls out fields from delimited text. The default delimiter is Tab.

syntax
cut -f LIST [-d DELIM] FILE
cut -f1,2 variants.tsv

Columns 1 and 2 of a tab-separated file.

cut -d, -f3- data.csv

Comma-separated, column 3 to the end.

grep -v '^##' variants.vcf | cut -f1-5 | head

Peek at CHROM POS ID REF ALT.

Warning

cut cannot handle quoted CSV fields that contain commas. Use csvcut or R/Python for real CSV.

grep — Search text

Prints lines that match a pattern. Quote the pattern in single quotes so the shell leaves it alone.

syntax
grep [-i] [-v] [-c] [-n] [-w] [-E] [-r] 'PATTERN' FILE...
grep 'ERROR' slurm-*.out

Which job logs mention an error?

grep -c '^>' contigs.fa

Count sequences in a FASTA (lines starting with >).

grep -v '^#' variants.vcf | head

-v inverts: skip header lines.

grep -n -i 'oom' job.log

Case-insensitive, with line numbers.

grep -E 'S0[1-5]_' samples.txt

Extended regular expressions.

zgrep -c 'PASS' calls.vcf.gz

Search inside a gzipped file.

Warning

grep '>' file is fine. grep > file (no quotes) truncates file and grep waits for input.

zcat / gzip — Compressed files

Most sequencing data arrives gzipped. The z-tools let you read it without unpacking to disk.

syntax
zcat FILE.gz   |   gzip [-k] FILE   |   gunzip FILE.gz
zcat reads.fq.gz | head -n 4

First FASTQ record.

gzip -k results.tsv

-k keeps the original file.

gunzip -t reads.fq.gz && echo OK

Test archive integrity after a transfer.

tar -xzf archive.tar.gz

Extract a .tar.gz (x = extract, z = gzip, f = file).

Redirection & pipes

Every command has three streams. Redirection decides where they come from and where they go.

Redirection visualizer

Pick an operator. The demo command is ls real.txt missing.txt, which produces one line on stdout and one on stderr.

redir = [
  {"op": "cmd", "stdout": "terminal", "stderr": "terminal", "note": "By default both output streams land on your screen, interleaved."},
  {"op": "cmd > out.txt", "stdout": "out.txt", "stderr": "terminal", "note": "stdout goes to the file (truncated first). Errors still show on screen."},
  {"op": "cmd >> out.txt", "stdout": "out.txt (append)", "stderr": "terminal", "note": "Same as >, but adds to the end of the file."},
  {"op": "cmd < in.txt", "stdout": "terminal", "stderr": "terminal", "note": "The command reads its input from the file instead of the keyboard."},
  {"op": "cmd 2> err.txt", "stdout": "terminal", "stderr": "err.txt", "note": "Only stderr (fd 2) is captured. Normal output still prints."},
  {"op": "cmd > out.txt 2> err.txt", "stdout": "out.txt", "stderr": "err.txt", "note": "Split data from diagnostics: the classic aligner pattern."},
  {"op": "cmd > all.txt 2>&1", "stdout": "all.txt", "stderr": "all.txt", "note": "First point stdout at the file, then make stderr a copy of stdout. Both end up in the file."},
  {"op": "cmd 2>&1 > all.txt", "stdout": "all.txt", "stderr": "terminal", "note": "Trap: stderr copied stdout while stdout was still the terminal. Only stdout reaches the file.", "trap": true},
  {"op": "cmd &> all.txt", "stdout": "all.txt", "stderr": "all.txt", "note": "Bash shorthand for > all.txt 2>&1."},
  {"op": "cmd | next", "stdout": "next (stdin)", "stderr": "terminal", "note": "Only stdout flows down the pipe. Errors bypass it and print to the screen."},
  {"op": "cmd 2>&1 | next", "stdout": "next (stdin)", "stderr": "next (stdin)", "note": "Merge stderr into stdout, then pipe both."},
  {"op": "cmd 2> /dev/null", "stdout": "terminal", "stderr": "/dev/null (discarded)", "note": "Throw errors away. Use sparingly."},
  {"op": "cmd | tee log.txt", "stdout": "terminal + log.txt", "stderr": "terminal", "note": "tee duplicates stdout to the screen and a file."}
]

0 1 2 — The three standard streams

Every process starts with three file descriptors: 0 = stdin (input, normally the keyboard), 1 = stdout (normal output), 2 = stderr (errors and warnings). Both 1 and 2 normally go to your terminal, which is why they look identical until you redirect one.

syntax
0 stdin   1 stdout   2 stderr
ls real.txt missing.txt > out.txt
ls: cannot access 'missing.txt': No such file or directory

The listing goes to out.txt; the error still appears on screen because it is stderr.

Tip

Slurm writes both streams to slurm-JOBID.out by default. Use #SBATCH -o and #SBATCH -e to split them.

> — Write stdout to a file

Sends stdout into a file, creating it if needed and truncating it to zero length first if it exists.

syntax
command > FILE
ls *.bam > bam_list.txt
set -o noclobber

Protect yourself: now > refuses to overwrite existing files. Use >| to force.

Warning

The file is truncated before the command runs. sort data.txt > data.txt leaves you with an empty file.

>> — Append stdout

Adds to the end of a file instead of replacing it.

syntax
command >> FILE
echo "$(date) started $SAMPLE" >> run.log

Build up a log across many commands.

for f in *.csv; do tail -n +2 "$f" >> merged.csv; done

Append every file minus its header.

Warning

Rerunning an appending script doubles the output. Clear the file first with > merged.csv if needed.

< — Read stdin from a file

Feeds a file into a command’s standard input. The command sees data but not a filename.

syntax
command < FILE
wc -l < samples.txt
96

Prints only the count, with no filename.

while read -r id; do echo "processing $id"; done < samples.txt

Loop over lines of a file.

2> / 2>&1 / &> — Redirect errors

Put a file descriptor number before the operator to redirect that stream. 2>&1 means ‘make stderr go wherever stdout currently goes’.

syntax
cmd 2> err.txt   |   cmd > all.txt 2>&1   |   cmd &> all.txt
bwa mem ref.fa r1.fq r2.fq > aln.sam 2> bwa.log

Data to one file, messages to another: the standard bioinformatics pattern.

./pipeline.sh > run.log 2>&1

Both streams into one file. Order matters: file first, then 2>&1.

./pipeline.sh &> run.log

Bash shorthand for the line above.

find / -name '*.fa' 2> /dev/null

Discard the permission-denied noise.

Warning

cmd 2>&1 > file is not the same as cmd > file 2>&1. Redirections run left to right; in the first form stderr copies stdout while it still points at the terminal.

| — Pipes

Connects one command’s stdout to the next command’s stdin. Nothing touches the disk in between.

syntax
cmd1 | cmd2 | cmd3
zcat reads.fq.gz | head -n 400000 | gzip > subset.fq.gz

Take the first 100,000 reads.

grep -v '^#' calls.vcf | cut -f1 | sort | uniq -c

Variants per chromosome.

cmd 2>&1 | less

Pipes only carry stdout. Merge stderr first if you want to page through errors too.

set -o pipefail

In scripts: make a pipeline fail if any stage fails, not just the last one.

tee — Split output: screen and file

Copies stdin to a file and to stdout, so you can watch output and save it at the same time.

syntax
cmd | tee [-a] FILE
./qc.sh 2>&1 | tee qc.log

Watch it live and keep a log.

./qc.sh | tee -a qc.log

-a appends instead of overwriting.

/dev/null — The bit bucket

A special file that discards anything written to it and is always empty when read.

syntax
cmd > /dev/null 2>&1
command -v samtools > /dev/null || echo 'load the samtools module first'

Check that a tool exists, without printing its path.

grep -q 'PASS' calls.vcf && echo found

grep -q is a cleaner way to stay silent.

Warning

Silencing stderr also hides real errors. Do it only when you know what you are throwing away.

<< EOF — Here-documents

Feeds a block of inline text to a command’s stdin. Quoting the delimiter ('EOF') turns off variable expansion inside the block.

syntax
cmd << EOF ... EOF   |   cmd << 'EOF' ... EOF
cat > samples.txt << EOF
S01
S02
S03
EOF

Write a small file without opening an editor.

cat > job.sh << 'EOF'
#!/bin/bash
#SBATCH -t 01:00:00
echo "running on $HOSTNAME"
EOF

Quoted delimiter: $HOSTNAME is written literally and expanded later, on the compute node.

grep -c x <<< "$SEQ"

Here-string: feed a single variable as stdin.

Warning

The closing EOF must be alone on its line with no leading spaces (unless you use <<- with tabs).

<( ) — Process substitution

Treats a command’s output as if it were a file. Great for tools that demand filenames.

syntax
cmd <(other_cmd) <(other_cmd)
diff <(sort a.txt) <(sort b.txt)

Compare two files ignoring order.

comm -12 <(sort ids_a.txt) <(sort ids_b.txt)

IDs present in both lists.

paste <(cut -f1 a.tsv) <(cut -f3 b.tsv)

Glue columns from two files side by side.

Warning

Bash only. It fails in sh with syntax error near unexpected token '('.

Quoting rules

Quotes decide what the shell expands and where it splits words. Most mysterious bugs start here.

'...' — Single quotes: fully literal

Everything between single quotes is taken exactly as typed. No variables, no globs, no backslash escapes. You cannot put a single quote inside single quotes.

syntax
'literal text'
echo 'Cost: $5 * 3'
Cost: $5 * 3
grep -E '^chr[0-9]+\s' file.bed

The safe default for regular expressions.

awk '{print $1}' data.tsv

Single quotes protect awk’s own $1 from the shell.

echo 'It'\''s done'
It's done

To include a quote: close, add an escaped quote, reopen.

"..." — Double quotes: expand, but do not split

Variables ($VAR) and command substitution ($(...)) still expand, but the result stays one word, and globs are not expanded. Inside, a backslash only escapes $, backtick, ", and \.

syntax
"text with $VAR and $(cmd)"
FILE="my reads.fq"
wc -l "$FILE"

Without quotes, wc would look for two files: my and reads.fq.

echo "Home is $HOME, today is $(date +%F)"
Home is /home/ada, today is 2026-10-05
echo "Price: \$5"
Price: $5

Escape a literal dollar.

Tip

Rule of thumb: always double-quote variable expansions, "$var", unless you specifically want splitting.

\ — Backslash escapes

Outside quotes, a backslash makes the next single character literal. At the end of a line it continues the command onto the next line.

syntax
\CHAR   |   long command \
ls My\ Data/

Escape a space (Tab completion does this for you).

sbatch --job-name=qc \
       --time=02:00:00 \
       --mem=8G run.sh

Split a long command over lines.

Warning

A space after the trailing backslash breaks line continuation, and the error is almost invisible.

$VAR ${VAR} — Variables

Assign with no spaces around =. Use braces when the name is followed by characters that could be part of a name.

syntax
NAME=value   "$NAME"   "${NAME}_suffix"
SAMPLE=S01
echo "${SAMPLE}_R1.fq"
S01_R1.fq

Without braces, bash looks for a variable named SAMPLE_R1.

OUT=${OUT:-results}

Default value if OUT is unset or empty.

f=reads.fastq.gz
echo "${f%.fastq.gz}"
reads

Strip a suffix: a clean way to build output names.

export THREADS=8

export makes the variable visible to programs you launch.

Warning

NAME = value (with spaces) runs a command called NAME. Bash replies NAME: command not found.

$( ) — Command substitution

Runs a command and pastes its output in place. Prefer $(...) over old-style backticks because it nests and reads clearly.

syntax
"$(command)"
N=$(wc -l < samples.txt)
echo "There are $N samples"
There are 96 samples

* ? [ ] — Globs (wildcards)

Unquoted *, ?, and [...] are expanded by the shell into matching filenames before the command runs. Quoting turns them back into literal characters.

syntax
*  any string   ?  one char   [abc]  one of   {a,b}  brace list
ls S0?_R1.fq.gz

S01 to S09, but not S10.

ls *_R[12].fq.gz

Both read pairs.

echo *.fasta
*.fasta

If nothing matches, bash passes the literal text *.fasta.

echo '*.fasta'
*.fasta

Quoted: never expanded.

for f in *.fq.gz; do echo "$f"; done

Loop over files the safe way. Never parse ls output.

Tip

{a,b} brace expansion is not a glob: it always expands, whether or not files exist.

spaces — Spaces in filenames

The shell splits words on spaces. A name like Field Notes.txt becomes two arguments unless you quote or escape it. Easiest fix: avoid spaces in names you create.

syntax
"Field Notes.txt"   'Field Notes.txt'   Field\ Notes.txt
cat "Field Notes.txt"
for f in *.txt; do mv "$f" "${f// /_}"; done

Replace spaces with underscores in every .txt filename.

find . -name '*.txt' -print0 | xargs -0 wc -l

-print0 and -0 keep odd filenames intact through a pipe.

nested — Quoting across ssh & sbatch --wrap

When a command string is handed to another shell, it is parsed twice: once locally, once remotely. Choose the outer quote type based on where you want variables to expand.

syntax
ssh host 'cmd $REMOTE_VAR'   |   sbatch --wrap "cmd $LOCAL_VAR"
ssh cluster 'echo $HOSTNAME'
login01

Single quotes: expanded on the remote machine.

ssh cluster "echo $HOSTNAME"
my-laptop

Double quotes: expanded locally before sending.

sbatch --wrap="gzip -k '$PWD/big file.tsv'"

Outer double quotes expand $PWD now; inner single quotes protect the space later.
